## Open questions
- Spec gap: §3.2's header table omits `installation_id`, but §10.2 and the ticket mirror it. Added `HeaderCodec.INSTALLATION_ID` (decimal string, >= 1) and put it in `ALL`.
- Annotation placement is mine: "may echo customer input" is a sibling `body_snippet_note` field, written only when `body_snippet` is non-null. §10.2 does not say where it goes.
- Spec wins, and it is thin: RAW `origin` is `{partition, offset}` with no topic, so `poison:{p}:{o}` can collide for a poison record from the main vs a retry topic. Revisit before E7's `dlq_entries` uniqueness.
- Spec/ticket mismatch: §10.2 says the indexer captures RAW key/headers; the ticket says the worker does. The builder takes them as plain arguments (no kafka-clients in `shared`), so either caller works.
- Builder rejects non-terminal classes and trailing bytes after the event JSON (my guards). `DlqEnvelopeBuilder.forEvent` parses via `EnvelopeSerde.fromBytes`, so a poison event throws `EnvelopeValidationException` there: callers route it to the RAW builder.
- RAW record mirrors only `failure_class` (`POISON_DESERIALIZATION`); `EXHAUSTED_POISON` is not produced here.

## Learning log for /notes write gof-builder (human's words are paraphrased from chat; polish before use)
- Q (human): what do `Origin` and the offset do; why store origin at all? Weak point: merged "offset of a record" with "committed offset" (watermark+1). Guessed retry topic = more headers (half right), partition cluster = attack (wrong: terminal != poison), offset = "idk". Correction (Claude): topic = failed on first contact vs after retries; partition = same PR key hashes to one partition, so a cluster means one bad PR/repo or one worker; offset = exact address to find the raw record (7 d) and log lines. The purpose is partly my inference; the spec only says "self-describing".
- Q (human): why a builder with setters instead of one 11-arg constructor? Answer given: "readability", "inconsistency if mixed". Correction (Claude): same-typed args (two Instants, two ints, two Strings) swap silently at compile and run time; named setters expose each role; `build()` is the single place that checks required parts.
- Q (human): what is the diff between `event` and `originalEvent`, who parses, who calls the builder? Answer (after explanation): event = the 11 known fields; original bytes may carry more (unknown fields), so the DLQ stores the bytes. Today nothing is missing in v1; it is insurance for additive schema evolution (§3.3) and exact replay.
- Human's confusion that helped: "who creates the envelope?" -> gateway creates the bytes; worker parses them with `EnvelopeSerde.fromBytes` and keeps the bytes for the DLQ.
- Human asked: what is GoF? (Gang of Four, 1994 book; Builder is one creational pattern; ours is the fluent variant, not the GoF Director/Builder interface: say so in Contrast).
