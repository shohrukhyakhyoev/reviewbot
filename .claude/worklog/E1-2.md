## Open questions
- Invented names (spec silent): transient classes `GITHUB_UNAVAILABLE`, `ANTHROPIC_UNAVAILABLE`, `AMBIGUOUS_POST`; catch-all transient `UNEXPECTED` (any exception nothing else classifies: 5 retries, then EXHAUSTED_UNEXPECTED); catch-all terminal `UNCLASSIFIED` (any 4xx no row covers, so I5 still holds). Confirm or rename before E4/E5 use them.
- Status mapping beyond §10.1 is unverified against real APIs (§19.10): GitHub 401/403-permission -> `INSTALLATION_REVOKED`; Anthropic 401/403 -> `MISSING_OR_INVALID_API_KEY`; Anthropic 400/404 -> `LLM_REQUEST`; 429 and rate-limit 403 -> `PROVIDER_THROTTLE`.
- `not_before` is dropped (empty -> defer schedule) when unparseable, in the past, or more than 1 day out: my guard, not in the spec.
- `AMBIGUOUS_POST` is never produced by the classifier (needs call context); E5 throws it for timeout-after-send.
- Anthropic's `anthropic-ratelimit-*-reset` headers are not parsed, only `retry-after` and `x-ratelimit-reset`.

- Post-review decisions (Claude, awaiting human's nod): R4 kept `UNCLASSIFIED` for GitHub 400/422 and Anthropic 413 as a recorded decision, so E7's alert rules must page on it like `LLM_REQUEST`; infra row is now `DependencyUnavailableException(Dependency)` -> `BreakerParked(Dependency)` (the INFRA kind has no `FailureClass`); `EnvelopeValidationException` and `HeaderDecodeException` both classify as `POISON_DESERIALIZATION`; R9 (status 0 sentinel) left for the human to accept or skip as a nit.
