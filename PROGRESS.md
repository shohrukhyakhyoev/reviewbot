- **Dedup metrics (E3-2):** `DedupMetrics` (package-private port): `hit()`, `checkFailedOpen(cause)`, `markFailed(cause)`; `LoggingDedupMetrics` logs the cause's class name only (a Redis message names the host) and no delivery id: a failed dedup drops nothing, so the id gives nobody an action. - **Gateway tests need Docker (E3-2):** `DeliveryDedupTest` runs `redis:7-alpine` in Testcontainers (surefire, `*Test`); the outage cases use a paused container (connection accepted, no reply), because a stopped one refuses at once and never exercises the timeout. The test builds its client through `GatewayConfig.redissonClient` (now public) so the real 2 s config is what is measured.
- **Gateway produce deadline (E3-3, [ADR 0001](docs/adr/0001-one-deadline-for-gateway-produce.md)):** one deadline (`ReviewbotProperties.timeouts().gatewayProduce()`, 5 s) covers `send()` and the ack wait; `max.block.ms` is the same value and the deadline is taken **before** `send()`. E6's retry/DLQ producers follow the same rule. Producer config only via `ProducerSettings`, records only via `ReviewRecordFactory`.
- **Produce failures are 503 (E3-3):** every produce failure, including what `send()` throws synchronously (closed producer, Kafka's `InterruptException`), is `UNAVAILABLE` → `503`, reported via `WebhookMetrics.produceFailed(cause)` by class name only. A record that cannot be built is a bug (500), not a 503, so building stays outside the try.
- **Gateway timing filter (E3-3):** `WebhookTimingFilter` (order `HMAC − 5`, `/webhook` only) records status + latency of every answer, incl. 401/413; it reads no body, and `HmacVerificationFilterTest` exempts it **by name** from the "nothing before HMAC" rule. Time sources are injected (`Clock` bean, `LongSupplier` nanoTime) so tests use fixed or fake clocks.
- **Tracker API (E4-0):** the poller calls `tracker.track(tp, offset)` per record at dispatch and carries the `TrackedOffset` to the drainer, which passes it to `markComplete` unchanged (generation fencing, I7). It commits `committable()` + 1 and calls `markCommitted(sameMap)` only in the `commitAsync` success callback and after `commitSync`.
- **Tracker failures are bugs (E4-0):** `track` on an unregistered partition or at/below the watermark → `IllegalStateException`; a duplicate `markComplete` → no permit, `IllegalStateException` (E4-2's drainer must not retry it); `markCommitted` beyond the watermark → `IllegalArgumentException` (the `+1` mistake).
- **ADR focus (E4-0, `CLAUDE.md`):** ADRs go to architecture/backend choices the human defends in interviews; test-tooling choices get a key-decision line instead ([ADR 0002](docs/adr/0002-seeded-random-property-tests.md) is the last of that kind).
- **Coalescer contract (E4-1):** the drainer calls `Coalescer.coalesce(batch)` once per drain and runs the Plan: superseded → `complete(rec, CoalescePlan.SUPERSEDED_OUTCOME)` (no DB row, no dedup marker, P1-1); poison → its `outcome` (RAW DLQ via E1-3, produced before `markComplete`, I9); jobs → core. A v1.5 command type must get its own rule in `Coalescer.applyRule` (exhaustive switch; commands are never collapsed).
- **`/tidy` before `/review-mine` (E4-1):** the `code-tidier` agent makes behavior-preserving clean-code edits on Delegate/Pair tickets only (the Own guard blocks it); it changes the fingerprint, so `/review-mine` runs after it.
- **Engine seams (E4-2):** E5 implements `JobExecutor` and `OutcomeHandler`; one instance of each is shared by every drainer (thread-safe). The handler never calls `markComplete` (it gets no receipt); the drainer does, once, after the handler returns or throws (I4, I5).
- **Dispatcher contract (E4-2):** `route()` runs on the poller thread and can throw (bad key, rejected executor) with the record already holding a permit. The executor must start drainers on other threads (`execute` runs inside `compute`). Engine metrics always go through `SafeEngineMetrics`.
- **Interrupts in drainers (E4-2):** a stray interrupt is cleared and reported (`strayInterruptCleared`) before each outcome handler; it is not a stop signal. Shutdown is §12's stop intake and wait. ADR candidate for E4-3/E4-4.
